# CodeGraph 嫁接计划：根节点源码解读分支与可核验问答

## 0. 已确认的最终架构边界

本计划以以下产品语义为准，后续实现不得将两条流程混为一谈：

```text
原资料文件夹
  │
  └─ 宿主 LLM ──> 原项目知识图
                    ├─ 既有知识节点、关系与构建流程：保持原样
                    │
                    └─ 根节点新增「源码解读」分支
                         └─ CodeGraph 索引用户授权的源码目录
                              └─ 宿主 LLM 整理为仓库／目录／文件／符号／关系导航节点
                                   └─ 在原知识节点旁显示“关联实现”卡片

CodeGraph 检索结果 ──> 作为应用内 LLM 回答代码问题的局部上下文
```

- **原项目知识图仍由宿主 LLM 按现有方式扫描资料文件夹并构建。** 不以 CodeGraph 替换、参与或重写此既有构建流程。
- 用户启用源码解读后，CodeGraph 仅索引其明确授权的源码目录；产物作为同一可视化知识图根节点下的新增子树呈现。
- 源码解读分支的节点和关系由 CodeGraph 事实驱动，并可由宿主 LLM 生成易读摘要；不得改写原有知识节点和既有关系。
- 原知识节点与源码节点之间仅增加可追溯的关联卡片／桥接链接；这不是将源码节点并入原有知识语义建模。
- 同一个 CodeGraph 索引还服务于应用内 LLM 问答，但问答检索不会反向修改原项目知识图。

## 1. 重新定义目标

KnowMap 的目标不是再实现一个代码智能平台。它要帮助用户理解一个项目：

1. 项目试图解决什么问题，为什么采用当前设计；
2. 这些设计分别由哪些模块、入口函数、配置和依赖实现；
3. 用户提问时，LLM 应基于恰当的少量源码片段回答，而非读取整个仓库或凭经验猜测。

因此，**CodeGraph 是可替换的源码事实、源码解读分支和上下文检索引擎**；KnowMap 是项目知识图谱、设计解释、学习卡片、来源审查和交互入口。当前实现以 `@colbymchenry/codegraph` 1.6.0 的本地 CLI 为准：使用 `init` / `files --json` / `context --format json` / `sync`，不接入此前讨论的 `codegraph-server` 协议。首期不自研 AST、多语言解析器、全量调用图、向量索引或代码治理平台。

```text
授权代码仓
   │
   ▼
CodeGraph（扫描、符号、关系、入口、局部上下文）
   │  MCP / 本地命令；只读、可替换
   ▼
CodeGraphAdapter（统一契约、权限、预算、版本）
   ├── SourceDecodeBranchBuilder → 挂在原图根节点下的源码解读子树
   ├── CodeContextService        → 给应用内 LLM 的最小源码上下文
   └── CodeEntryLink             → 原知识节点的“关联实现”卡片
                                      │
                                      ▼
KnowMap（知识图、卡片、问答、审查、确认、源码跳转）
```

## 2. 范围与非目标

### 本期做什么

- 用户构建项目知识图后，可选择是否在其根节点下追加独立的“源码解读”分支。
- 连接用户授权的本地仓库，并由 CodeGraph 建立或查询代码索引。
- 根据用户问题取得**部分、可定位、可审计**的源码上下文，交给应用内 LLM 回答。
- 从项目知识节点跳转到其关联实现：依赖库、入口函数、文件、符号、行号和 revision。
- 使设计解释、源码证据、LLM 推断和用户确认保持清晰分层。
- 对索引、提问与停止任务保留状态、错误和可恢复检查点。

### 本期明确不做

- 不复制 CodeGraph 的 tree-sitter、多语言解析、嵌入、调用图和影响分析实现。
- 不承诺“全仓精确理解”或把整个仓库发送给模型。
- 不把文件、函数和调用边强行变成普通知识概念卡。
- 不自动执行代码、安装依赖、运行构建或 clone 远程仓库。
- 不以 CodeGraph 的全部工具为集成范围；只接入问答和导航所需能力。

## 3. 用户可见的产品流程

### 3.1 构建选择

用户发起“为项目构建知识图谱”时，先完成现有的项目目标、需求、架构与模块知识构建。随后明确询问：

> 是否启用“源码解读”？启用后会只读分析你授权的本地代码仓。在应用内配置LLM时，可以选择再次授权代码仓并检索相关源码片段拼接后发送给LLM提高回答准确度

| 用户选择 | 结果                                                                                               |
| --- |----------------------------------------------------------------------------------------------------|
| 不启用 | 按照原本逻辑生成项目知识图，不生成源码解读分支。                                                   |
| 启用 | 原项目知识图先按原流程完成；随后创建仓库连接，在其根节点下追加“源码解读”分支，并建立关联实现卡片。 |
| 稍后启用 | 已有项目知识图保持不变，之后从应用设置添加仓库连接。                                               |

### 3.2 同图呈现的两类节点与桥接

| 原项目知识节点 | 根节点下的源码解读分支节点 |
| --- | --- |
| 目标、架构决策、模块职责、工程约束、可靠性机制、验证策略 | 仓库、目录/包、文件、符号与 CodeGraph 提供的关系 |
| 回答“为什么需要”“选择了什么”“边界是什么” | 回答“在哪里实现”“谁调用谁”“相关入口和测试在哪里” |
| LLM 新结论需审查与确认 | 文件、符号、行号和 revision 是源码事实 |

两类节点在同一图谱界面中呈现，但只有源码解读分支新增节点；原有知识节点和关系不变。两者只通过显式桥接关系连接：`IMPLEMENTED_BY`、`CONFIGURED_BY`、`TESTED_BY`、`DEPENDS_ON`。一个桥接关系须包含源码范围或用户确认理由；LLM 候选不能伪装成源码事实。

### 3.3 卡片导向

知识节点的卡片继续使用其自身合适的理论、应用或工程栏目，并额外提供“关联实现”：

- 主要入口函数和实现符号；
- 所在文件、行号、当前 revision；
- 直接关联的库及其配置来源；
- 测试或验证入口；
- 链接的来源：CodeGraph/清单事实、LLM 候选、用户确认。

卡片不会把完整源码复制进正文。点击“查看实现”才打开局部源码预览或源码解读节点。

## 4. 最小集成架构

### 4.1 CodeGraphAdapter

新增单一适配边界，不让 UI、聊天 Agent 或既有项目知识图构建逻辑直接调用 CodeGraph MCP：

```ts
interface CodeGraphAdapter {
  indexRepository(input: RepositoryConnection): Promise<IndexResult>;
  getRepositoryStatus(repositoryId: string): Promise<RepositoryStatus>;
  findEntryPoints(query: CodeQuery): Promise<CodeReference[]>;
  findSymbols(query: CodeQuery): Promise<CodeReference[]>;
  getRelatedContext(input: ContextRequest): Promise<CodeContextBundle>;
  reindexChangedFiles(input: ReindexRequest): Promise<IndexResult>;
}
```

适配器通过受控后端启动本地 CLI，不由浏览器或 LLM 直接执行。首期使用 `files --json` 建立导航、`context --format json` 获取带行号代码块、`init` 与 `sync` 更新索引。CodeGraph 不可用时，应用正常保留知识图，只禁用依赖源码的问答并明确说明原因。

### 4.2 受控代码上下文

`CodeContextService` 接收“用户问题 + 当前知识节点/文件/符号”，并按以下顺序组装上下文：

1. 当前项目知识节点与其已确认的 `CodeEntryLink`；
2. CodeGraph 返回的目标符号或入口函数；
3. 与问题直接相关的一跳调用者、被调用者、类型或配置；
4. 必要的测试片段；
5. 路径、符号、行号、revision、内容 hash 与不确定性说明。

上下文受文件数、代码行数和 token 预算限制。超出预算时优先保留目标实现和其最直接的依赖，并将“未纳入的范围”写入回答限制；不能静默截断后声称已完整核验。

```ts
interface CodeCitation {
  path: string;
  symbol?: string;
  startLine: number;
  endLine: number;
  revision: string;
  contentHash: string;
  source: "codegraph-fact" | "manifest-fact";
}
```

### 4.3 源码解读分支构建

`SourceDecodeBranchBuilder` 在**原项目知识图已经生成后**运行，接收根节点 ID 与 CodeGraph 的仓库、目录、文件、符号和关系事实：

1. 在根节点下创建唯一的“源码解读”分支根节点；
2. 将仓库、目录、文件、关键符号和有限的调用／依赖关系创建为该分支的新节点；
3. 可请求宿主 LLM 为新节点生成摘要、用途说明和学习卡片，但结构、路径、行号、revision 仍以 CodeGraph 事实为准；
4. 对原知识节点只创建 `CodeEntryLink`，在卡片中展示“关联实现”，绝不修改它们已有的文本、关系或来源；
5. 分支建立失败时保留原项目知识图，并将源码解读状态标为失败或可重试。

该构建器不是 `KnowledgeGenerator.generate()` 的前置步骤：既有资料扫描与项目知识图生成在不启用源码解读时必须字节级行为一致；源码分支是后置、可取消、可重试的附加任务。

### 4.4 知识—代码链接

```ts
interface CodeEntryLink {
  knowledgeNodeId: string;
  relation: "IMPLEMENTED_BY" | "CONFIGURED_BY" | "TESTED_BY" | "DEPENDS_ON";
  citation: CodeCitation;
  library?: { packageName: string; version?: string; manifestPath: string };
  source: "codegraph-fact" | "manifest-fact" | "llm-candidate" | "user-confirmed";
  rationale?: string;
}
```

生成规则：

- CodeGraph 找到的入口、符号、调用与测试可直接成为 `codegraph-fact`；
- `package.json` 或 lockfile 中的依赖是 `manifest-fact`；
- “这个实现体现了任务可靠性”属于 LLM 解释，只能成为 `llm-candidate`，需审查确认；
- 文件变更后依 `revision + contentHash` 标为 stale，不能继续当作当前证据。

### 4.5 受控后端联动

浏览器绝不直接读取本地代码。后端仅能访问允许 workspace 内、用户授权的仓库；默认排除 `.git`、`.env*`、私钥、`node_modules`、构建产物、缓存与二进制。仓库源码、README 与注释均视为不可信输入，不能作为 Agent 指令执行。

## 5. LLM 问答流程

```text
用户提问
  → 判断是否需要源码证据
  → 读取当前知识节点与其已确认链接
  → CodeGraph 检索目标符号和局部关系
  → CodeContextService 预算化选取少量源码片段
  → LLM 回答
  → 输出“设计解释 + 实现说明 + CodeCitation + 已知限制”
```

回答必须分清三层：

| 层级 | 示例 | 表达方式 |
| --- | --- | --- |
| 源码事实 | `cancelAgentJob` 在某文件某行定义 | 附源码引用，明确为已核验。 |
| 结构推断 | 调用链表明取消请求会经过后台任务服务 | 附涉及符号，说明由静态关系推得。 |
| 设计解释 | 分批持久化是在降低长任务丢失风险 | 关联项目知识卡；若无文档或确认，标为解释候选。 |

当 CodeGraph 未索引、索引过期或没有找到足够证据时，Agent 只回答现有知识图可支持的部分，并明确“未完成源码核验”。

## 6. 重构后的开发阶段

### P4-0：冻结边界与验证 CodeGraph 可接入性

- 确认 CodeGraph 的本地安装、MCP/命令调用方式、许可证、版本固定方式与 Windows 兼容性。
- 用一个小型中立 TypeScript fixture 验证：入口、符号、局部上下文、调用邻居、测试和单文件重索引是否可稳定取得。
- 定义 `CodeGraphAdapter`、`CodeCitation`、`CodeEntryLink` 和索引状态契约；不改现有知识数据格式。

**验收**：不依赖 LLM 即能从 fixture 返回路径、符号、行号、revision；CodeGraph 缺失时应用可降级而不影响普通知识图。

**当前状态：已完成。** 已验证 `@colbymchenry/codegraph` 1.6.0；示例项目索引得到 197 个文件、2,272 个符号和 5,493 条关系。

### P4-1：仓库连接、授权与轻量源码解读入口

- 增加“是否启用源码解读”的构建选择和应用设置入口。
- 实现受控本地仓库连接、允许目录校验、排除策略、revision 记录和可取消索引任务。
- 将 CodeGraph 的索引状态显示为 `idle / indexing / ready / failed / cancelled / stale`，并与“完成”严格区分。
- 在**原图根节点下**建立轻量“源码解读”导航分支：仓库、目录、文件和由 CodeGraph 命中的符号；不复制全量内部事实图。

**验收**：用户可启用、停止、重试或稍后启用；未授权目录和敏感文件不进入索引；停止不是完成；不启用时原项目知识图构建结果与接入前保持一致。

**当前状态：已完成核心路径。** 用户可在 Agent 面板连接本地源码目录；索引成功后会通过独立、版本化补丁在原图根节点下追加源码解读、仓库、目录和文件节点，原有节点、卡片与关系不被重写。

### P4-2：最小源码上下文问答

- 实现 `CodeContextService`，优先查询当前节点关联实现，再按问题查询 CodeGraph。
- 支持四类问题：定义在哪里、某功能如何实现、某设计由哪些入口/模块支撑、某段代码如何工作。
- 为 Agent 新增 `codeCitations` 输出与前端的文件/符号/行号展示。
- 加入上下文预算、排除文件检查、无证据降级和索引过期提示。

**验收**：测试问题均仅注入命中的少量源码；答案的每个“源码事实”均可跳转到正确引用；模型无法获得敏感或无关文件。

**当前状态：已完成核心路径。** 后端用 CodeGraph JSON 代码块构造受控上下文；应用内 LLM 只接收命中的局部片段。命中的符号会增量写入“文件 → 符号”导航层，回答显示文件、行号、revision 与内容哈希。

### P4-3：项目知识节点的关联实现

- 在项目知识卡增加“关联实现”栏目和跳转入口。
- 源码解读节点只新建在根节点的“源码解读”子树下；不得作为原知识节点的替换或重写。
- 从 CodeGraph 入口/符号、依赖清单、相关测试生成候选链接。
- 事实链接可直接显示；涉及职责、动机、可靠性意义的链接进入既有 Review → diff → 用户确认流程。
- 从源码节点反向显示它支撑的项目知识节点。

**验收**：至少三个项目知识节点能定位库与主要入口函数；源码节点均位于根节点的源码解读分支；用户能分辨“源码事实”“模型候选”“已确认解释”。

### P4-4：增量刷新与长期运行

- 通过 CodeGraph 的指定文件/工作区增量索引更新变更内容，而不是自建 Git/AST 增量算法。
- 记录每次索引的 revision、时间、范围、成功/失败/取消原因和检查点。
- 当引用符号或文件发生变化时，标记关联卡片与链接 stale，提示复核；不自动覆盖人工知识。

**验收**：修改一个文件后可仅刷新受影响源码上下文；旧卡片保留且明确过期；失败、取消、预算耗尽和完成都有持久状态。

### P4-5：真实项目验收与是否扩展的决策

- 用本项目自身和一个外部小型 TypeScript 项目测试连接、上下文问答、知识链接、变更刷新、取消恢复。
- 度量检索命中率、错误引用率、平均上下文大小、索引耗时和用户确认率。
- 依据结果决定是否接入影响分析、更多语言或向量检索；任何扩展均须证明能改善“理解设计如何落到代码”，而非仅增加工具数量。

**验收**：形成可复现的验收报告，并只将通过的能力设为默认可用。

## 7. 测试与可靠性要求

| 层级 | 核心验证 |
| --- | --- |
| 适配器契约 | CodeGraph 输出缺字段、超时、版本变更、进程不可用时的降级与错误分类。 |
| 安全 | 目录越界、符号链接、`.env`、密钥、超大文件、恶意注释指令均不能进入模型上下文。 |
| 上下文 | 目标符号优先、预算限制有效、无关文件不进入 prompt、引用与源码内容 hash 一致。 |
| 语义 | 事实、结构推断、设计解释在 UI 和输出中标签不同；LLM 候选未经确认不能写为正式链接。 |
| 长任务 | 索引与刷新分批写检查点；取消、失败、预算耗尽、完成持久区分，可重试。 |
| 回归 | 不启用源码解读时，既有构建、资料补充、深度研究、滚动摘要和知识图功能不受影响。 |

## 8. 决策原则

1. **优先正确上下文，不优先完整代码图。** 能准确回答一个功能如何实现，比展示全仓调用边更重要。
2. **优先嫁接，不重复造轮子。** CodeGraph 负责代码结构能力；KnowMap 只保留产品必需的统一契约与上下文选择。
3. **事实、解释、确认分离。** 行号、符号和 revision 是事实；“为什么这样设计”是解释；进入知识图的解释需要审查。
4. **局部、可控、可追溯。** 只发送用户授权、问题相关且受预算限制的片段；每个源码结论可返回到代码位置和版本。
5. **可选且可降级。** CodeGraph 未安装、不可用或用户不授权时，KnowMap 仍是完整的项目知识图谱应用。
