# 工作流 4：知识接入工作流

## 目标
将用户提供的资料（对话/摘要/论文/文档）接入当前知识图谱，提取信息并更新知识网络。

## 触发条件
- 用户上传或提供资料
- 用户要求"总结当前对话并补充知识"
- 用户要求"将这段对话接入知识图谱"

## 输入
- 资料类型：conversation / summary / paper / document
- 资料内容
- 当前知识图谱状态

## 步骤

### Step 1：资料类型识别
1. 判断资料类型（对话/摘要/论文/文档）
2. 选择对应的提示词模板
3. 解析资料内容

### Step 2：知识提取
1. 提取资料中的核心观点、结论和知识点
2. 识别方法、算法、参数和工程取舍
3. 区分"已确认的事实"和"讨论中的推测"
4. 只把可验证的事实作为知识候选
5. 口语化表达转为规范的学术表述

### Step 3：图谱检索与匹配
1. 先用图谱检索判断知识点是否已存在
2. 已存在 → 续写该节点的对应栏目
3. 确认是新增知识 → 才创建新节点
4. 匹配判定三阶段：
   - 阶段 1：精确匹配（id/名称完全一致）
   - 阶段 2：语义匹配（概念相似）
   - 阶段 3：人工确认（模糊匹配）

### Step 4：节点粒度约束
1. 一个节点只放一个东西，由 nodeType 决定
2. 禁止多个并列概念/方法/问题放一个节点
3. problem 节点只描述问题/现象本身，禁止混入解决方法
4. 多个方法必须有共性父节点
5. 节点名称 ≤15 字，禁止并列连词
6. shortFact ≤50 字

### Step 5：关系建立
1. 新增节点必须挂到图谱中最相关的已有节点下
2. 不要都挂到根节点
3. 生成父子关系和跨节点语义关系
4. 关系类型从 Profile.edgeTypes 中选择

### Step 6：审查与合并
1. 语义审查：节点粒度、栏目匹配、来源可验证
2. 结构校验：边端点存在、域归属正确
3. 批量合并：收集所有候选后统一比对
4. 写入图谱

## 输出
- 更新后的知识网络
- 新增节点列表
- 更新栏目列表
- 新增关系列表

## 验证标准
- [ ] 知识点正确提取（无遗漏、无幻觉）
- [ ] 已存在节点正确续写（不重复创建）
- [ ] 新增节点符合节点粒度约束
- [ ] 关系合理（父节点正确、跨节点关系有意义）
- [ ] 来源可验证（未经外部检索的标注"待核验"）
- [ ] 不捏造引文

## 常见问题
| 问题 | 解决方案 |
| --- | --- |
| 知识点重复创建 | 增强图谱检索，先检索再创建 |
| 节点包含多个概念 | 节点粒度审查，反馈模型拆分 |
| problem 节点混入解决方法 | PROBLEM_NODE_HAS_SOLUTION 审查，反馈模型分离 |
| 来源不可验证 | 标注"待核验"，不捏造引文 |
| claim id 重复 | 使用唯一 id 生成器，批量合并时去重 |
| 节点都挂到根节点 | 在提示词中强调挂到最相关的已有节点 |
