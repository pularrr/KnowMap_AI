# readme_2 · FMCW Radar Knowledge Graph（AI 知识图谱生长引擎）

> **一句话定位**：一个**图谱原生的 AI 应用**——内置一套「治理型 Agent 管道」，让插入式的通用 LLM（GPT / DeepSeek / 本地模型均可）一接入就获得**可审计、可回滚、需用户确认**的知识图谱生长能力：读图 → 判缺口 → 提案 → 结构审查 → 确定性构建 → 用户确认 → 版本化落库。领域背景是 FMCW 雷达信号处理与数据关联知识图谱（检测/估计/关联/跟踪/系统实现/AI 学习等 11 个语义域）。其核心理念是**内生 AI：认知与治理分离**。

---

## 1. 项目能做什么 & 为什么做这个项目

**能做什么**
- 浏览与问答一个结构化 FMCW 雷达知识图谱：导航树 + SVG 图谱 + 四页签知识卡（理论知识 / 应用知识 / 其他知识 / 历史修改）+ Agent 面板（提问 / 深度搜索 / 总结），支持 `?node=` URL 直达。
- 做**知识缺口分析**：检查 13 类卡片维度的覆盖缺口，给出有界邻域候选（只读、不落库）。
- 提供**图谱生长闭环契约**：LLM 接入后可「提案 → 结构审查 → 确定性补丁 → 用户确认 → 版本化」，全程可审计、可回滚。

**为什么做**
通用 LLM 接知识图谱时容易「乱写、写错、写后不可追溯」。本项目要证明一种更稳健的范式：**让 LLM 只负责需要判断的地方（候选生成、缺口识别、语义归类、内容审查），把确定性的环节（结构门禁、GraphPatch 构建、状态机、版本仓、审计）交给代码**。并把「离线」当作安全地板与测试基座，把「在线 LLM 介入」当作一等公民体验（对话式生长、矛盾发现、缺口提案）。

## 2. 怎么使用这个项目

**环境**：Node.js ≥ 22.13（Windows 用 `npm.cmd`）。**无需任何 API Key、数据库、网络**。

```powershell
npm.cmd ci          # 按锁文件安装依赖
npm.cmd run dev     # 开发服务器 → http://localhost:3000
# 生产：
npm.cmd run build && npm.cmd run start
# 验证（31 项测试）：
npm.cmd test
```

**界面导览**
- 左侧导航树与中间 SVG 图谱共享父层级；点击节点，右侧打开知识卡。
- 右侧知识卡四个页签：理论知识 / 应用知识 / 其他知识 / 历史修改（每节点最近 15 条）。
- 底部 Agent 面板（当前节点优先）：**提问**→基于当前节点卡片作答并标注来源；**深度搜索**→检查 13 类卡片维度缺口并给出有界邻域候选（只读、不落库）；**总结**→汇总结论供后续检索。
- 历史记录存浏览器 localStorage，服务端零持久化。

**当前边界（如实说明）**：v0.1.0 未接入真实 LLM，Agent 面板为本地确定性实现（候选只读、不写入图谱，UI 不伪装联网检索）；写路径完整安全链路已实现并测试，但 UI 写入入口随 LLM 接入一并开放。

## 3. 项目最终获得的效果

- **认知层离线完整可用**：无需任何 API Key 即可浏览、问答、缺口分析——这使项目成为一个「安全地板 + 测试基座 + 降级路径」。
- **图谱本体成型**：114 节点（98 历史零损迁移 + 16 种子扩展）/ 11 语义域 / 5 视觉分支 / 25 条语义边 / 21 条 LaTeX 公式（KaTeX 渲染）；节点只表实体身份，12 类语义边、13 类卡片栏目（定义/原理/假设/工程取舍/失效模式/验证/对比/误区…）。
- **治理层经测试验证**：宪法式校验器、同层优先有界遍历、四 Agent 契约、GraphPatch、一次性确认凭据、幂等提交、追加式回滚、审计重放、版本仓（1 最近 + 2 历史）——**31 项测试全绿**。
- **LLM 接入契约就绪**：`GeneralLlmProvider` 中立端口 + 能力白名单 + 摄取/提案/审查契约已定义，在线交互作为亮点推进（P1.3 / P1.4）。

## 4. 项目亮点（如何处理工程问题）

| # | 亮点 | 工程价值 / 解决的问题 |
|---|---|---|
| 1 | **写路径四道闸** | 模型只回答/抽取 → 抽取物为「待审查声明」→ Review 结构门禁 → Build 确定性 dry-run → 用户确认（一次性 nonce）→ 追加新 revision，永不改写历史；把「AI 乱写」变成有闸门的工程问题 |
| 2 | **认知与治理分离** | LLM 只在判断点介入，结构/补丁/状态机/版本/审计由确定性代码实现，模型侧不存在任何仓库或变更方法（capabilityPolicy 白名单） |
| 3 | **宪法式校验器** | 层级/环/边权/证据约束校验，保证图谱结构合法，从源头拦住非法写入 |
| 4 | **确定性 GraphPatch** | 纯函数（同提案必同 patch id），可预览差异、可幂等提交、可审计重放 |
| 5 | **一次性确认凭据 + 追加式回滚** | 确认用 nonce 防伪造；版本仓只追加不覆盖，回滚即重放，历史可追溯 |
| 6 | **同层优先有界遍历** | 深度搜索只在有界邻域内候选，确定性/去重/环安全，避免无界爆炸 |
| 7 | **离线优先 L0** | 离线实现是安全地板+测试基座+降级路径，而非妥协形态；在线 LLM 是亮点而非前提 |

## 5. 技术路线（AI + 前后端开发视角）

**AI 层（概率性内核 · 内生 AI）**
- **四 Agent 契约分工**：
  - Knowledge：候选知识/关系/卡片生成、缺口识别（认知层 → LLM 判断点，离线为规则实现）；
  - Review：结构安全审查（层级/环/证据/悬空引用）——治理层确定性门禁；
  - Build：生成确定性 GraphPatch + 差异预览（纯函数）；
  - Development：编排（预览 → 用户 confirm/revise/reject → 版本）——治理层状态机。
- **LLM 接入契约（面向开发者）**：`core/agent/provider-boundary.ts` 定义 `GeneralLlmProvider.respond(request)` 为模型唯一端口——入参纯文本上下文，出参仅 `{ text, extractedKnowledge? }`；`AgentOrchestrator.handle()` 按意图（回答/总结供图/提案更新）路由，模型侧无仓库方法。
- **能力边界**：`capabilityPolicy` 保证 general-llm 仅具 `answer`、`extract-claims`；`contracts.ts` 定义六类 Agent 接口 + 提案/审查/补丁/审计事件；`core/ingestion/contracts.ts` 定义多源输入（对话/论文/文档/媒体）→ 片段 → 声明 → 匹配候选的结构化通道。

**后端 / 领域引擎层（确定性外壳）**
- `core/knowledge/`：知识模型 schema（节点/12 边/13 卡/公式）、validation 宪法、traversal 同层优先有界遍历、便携包。
- `server/agent/`：离线工作流（审查门禁 → dry-run → 确认凭据 → revision+1 → 审计重放）、版本仓、审计重放；`server/knowledge/` 磁盘版版本化知识仓。
- `core/agent/`：Agent 契约、能力边界、图操作、离线实现；`data/`：仓库接口 + 静态实现，98 节点零损迁移 + 16 节点种子切片。

**前端层**
- Next.js 16 + React 19 + Tailwind 4 + KaTeX + zod + TypeScript 5.9（测试用 Node 原生 test runner + Vite）。
- `features/knowledge-graph/`：导航树、SVG 图谱、知识卡、公式渲染；`features/agent/`：Agent 面板 + 离线认知实现（问答/深度搜索/总结）。
- 确定性渲染：图谱/卡片/公式全部由本地数据确定性生成，历史存 localStorage，服务端零持久化。

**工程化**
- 31 项自动化测试覆盖：98 节点零损往返、领域与层级校验、同层优先遍历的确定性/去重/环安全、可见图三列投影、公式与 UI 契约、四 Agent 确认前零写入/幂等/伪造拒绝/回滚追加修订/审计重放、深度搜索锚定覆盖与只读候选。
- 设计取向：**写路径铁律 + 模型侧零写能力 + 离线优先**，用「确定性外壳包住概率性内核」的方式把 LLM 的不可控性关进可审计、可回滚、需确认的笼子里。
